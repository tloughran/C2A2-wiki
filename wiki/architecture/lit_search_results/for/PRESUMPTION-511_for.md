  Strength of support: Strong
  Summary: This item states a distinction that the National Academies formalised for exactly this purpose, and the supporting sentence is unusually direct: reproducibility and replicability "do not imply correctness." The NASEM definitions make the item's diagnosis precise — running the same code over the same corpus is reproducibility, which is a property of the computational pipeline and is expected as a baseline rather than earned as evidence; obtaining consistent results by an independent route is replicability, and only that speaks to the finding. The item's strongest clause is the one about systematic defects, and it has direct empirical backing from the same batch's other work: deterministic static analysers with false-alarm rates above 95% reproduce every false alarm exactly, so reproduction would validate a detector that is almost entirely wrong. That is not a hypothetical for C2A2 — ASSUMPTION-489 describes a detector in that state in this very vault, which makes the item's inference from the Summa run's use of "independently" concrete rather than abstract. The correlated-error literature supplies the general law under which both this item and 15c's REVISE-233 concern fall: the evidential value of agreement scales with method independence, and where a common generating mechanism is shared, concordance is close to uninformative. The item's proposed audit — for each verification figure, ask whether a second method exists, and count how many standing figures are single-method — is the correct and cheap triangulation inventory.
  Caveats: (a) NASEM also notes the converse, that failure to reproduce does not imply incorrectness; the item does not overclaim here, but a reader applying it aggressively might. (b) Reproducibility is not worthless. It excludes a real and common failure class — environment drift, non-determinism, undocumented manual steps — and NASEM treats it as a necessary baseline. The correct reading of 511 is that reproduction is necessary and insufficient, not that it is empty, and the word "independently" in a verification report should be reserved for the replicability case rather than dropped. (c) Genuine method independence is expensive and sometimes unobtainable: a second word-counting implementation written by the same agent from the same specification shares the specification, which is where ASSUMPTION-490's definitional disagreement actually lives. The remedy risks producing nominal independence over a shared definitional defect — the same trap ASSUMPTION-483 documents for 15a/15b. Independence must be engineered at the definition layer, not just at the code layer. (d) Sources 3 and 4 are preprints of unverified peer-review status; source 1 carries the weight and is sufficient on its own.
