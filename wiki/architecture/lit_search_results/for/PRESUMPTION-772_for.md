  Sources:
    1. Rubin, D.B., 1976. "Inference and missing data." Biometrika 63(3):581-592. — The origin of the MCAR/MAR/MNAR taxonomy. The relevant consequence: when missingness depends on the unobserved value itself (MNAR), treating absent data as an observation of absence produces biased inference, and the bias is not correctable from the observed data alone. A null that is really a non-execution is MNAR in the sharpest way — it is missing *because* the mechanism failed. [canonical; cited from domain knowledge]
    2. Prometheus / Alertmanager "Watchdog" alert and the dead man's switch pattern (documented in ilert docs, "Prometheus Heartbeat Example"; oneuptime, "How to Set Up Heartbeat and Dead Man's Switch Alerts," 2026-02-06). — The single most direct operational analogue. The stated failure mode is verbatim the one 14b found: a query such as `rate(http_requests_total[5m]) > 100` "returns nothing if the time series disappears — it does not return zero, it returns empty," and "most alerting systems treat empty query results as 'no data' and do nothing, which creates silent outages." The remedy is an always-firing alert routed to an external heartbeat monitor, so that the *absence of the null-report itself* becomes detectable. [unverified — from search snippets; vendor documentation, authoritative as practice]
    3. Kestra, 2024. "Building A New Liveness and Heartbeat Mechanism For Better Reliability." — Engineering account of retrofitting liveness signalling onto a workflow orchestrator specifically because stalled executions were indistinguishable from idle ones. Empirical precedent from a pipeline scheduler, which is the closest system class to a C2A2 monitoring cycle. [unverified — from search snippet; vendor engineering blog]
    4. Practitioner data-engineering literature on silent pipeline failure (phData, "Trials and Tribulations Preventing Silent Data Loss"; anomalyarmor.ai, "Data Pipeline Monitoring"; dev.to/137foundry, "The Real Cost of Silent Data Pipeline Failures"). — Converges on the definition: "a silent failure happens when a data pipeline technically succeeds, but the data it produces is incomplete." The inverse of C2A2's error and therefore supportive by symmetry — the presence/absence pattern of reports is itself data, and here the pattern (4 nulls then 12/12) is the diagnostic. The four nulls, if non-executions, contributed zero information while consuming the register's confidence as though they had contributed four cycles' worth.   Strength of support: Strong

  Summary: The corrective proposition is strongly supported, and the operational monitoring literature has converged on a specific, cheap remedy. The core distinction — empty is not zero — is stated almost verbatim in the Prometheus/dead-man's-switch material, and the standard fix (an always-firing heartbeat plus per-stage freshness and volume checks against historical baseline) is exactly the instrument whose absence 14b infers. Rubin's MNAR framework supplies the theoretical reason the error is not self-correcting: if nulls arise from mechanism failure, no amount of downstream analysis of the reported nulls recovers the truth, because the missingness is informative. The 12/12 subsequent hit rate is, in this framework, about as strong an internal signal as a pipeline can generate that its prior nulls were non-executions rather than measurements. The agent-specific evidence that self-reported completions are unreliable at high base rates (source 6) is the most directly relevant contemporary work and the least verified.

  Caveats: (a) The strongest sources are grey literature — vendor docs and engineering blogs. They are authoritative about practice but are not measurements, and none quantifies how often nulls are non-executions. (b) Rubin's framework is about statistical inference from incomplete samples, not about process attestation; the transfer is conceptually sound but it does not license any specific correction procedure here. (c) An alternative benign explanation exists and this search cannot exclude it: the four cycles may have genuinely searched and genuinely found nothing, with the fifth cycle's 12/12 explained by a change in query strategy, corpus, or source availability rather than by non-execution. Volume-baseline monitoring would not distinguish these either; only execution-level evidence (tool-call records) would — which links this item to PRESUMPTION-777. (d) Publication bias: the monitoring literature is written by vendors selling detection, so it over-represents the severity of undetected nulls.
