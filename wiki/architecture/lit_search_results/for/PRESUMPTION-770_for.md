  Summary: This is the best-grounded item in the batch, because transaction processing solved exactly this problem and named it. The corrective proposition is not merely supported — it is the definition of a commit. ARIES makes the point sharply: durable and committed are different states, recovery must presume the difference, and a system without an undo phase will silently promote loser-transaction writes to the status of results. Two-phase commit supplies the vocabulary for the specific gap (marks written in what should have been a prepare phase, read as though a commit had occurred). Pillai et al. supply the empirical precedent that real applications get this wrong routinely, so the finding does not imply unusual carelessness. The agent-specific literature adds a sharper concern: in systems where an agent can write a completion marker, that marker becomes an attack surface as well as a crash hazard, and at least two 2026 benchmarks appear to treat forged completion markers as a measured failure class.

  Caveats: (a) The transaction literature assumes a coordinator and a recoverable log. C2A2's marks live in human-readable markdown with no commit record and no recovery pass, so the remedy is not "adopt ARIES" but "define a completion point and make marks provisional until it is reached" — a design translation this literature does not perform. (b) The tension named in 14b's search strategy is real and the literature confirms it rather than resolving it: idempotence and resumability *want* mid-run marks to survive (so work is not repeated), while attestation wants them not to (so authority is not fabricated). ARIES resolves this with a log that distinguishes the two; a system with one channel for both cannot. This is the genuine open problem and I found no source addressing the trade-off directly for agent pipelines. (c) The 14b item's inference that readers accorded the marks authority is not something literature can support; it requires evidence from C2A2's own downstream consumption. (d) Sources 5 and 6 are the most directly on-point and the least verified.

  Search scope: Comprehensive on transaction recovery, WAL and 2PC (the core of the answer). Moderate on application-level crash consistency. Preliminary on the idempotence-versus-attestation trade-off in agent pipelines, which I judge to be a genuine literature gap — see novelty note below.

  Partial novelty note (not a full NOVELTY-FLAG, since the parent claim is well supported): I found no literature addressing how to reconcile resumability (which requires durable mid-run progress marks) with attestation (which requires marks to be void absent a completion record) in *agent* pipelines whose state store is human-readable prose rather than a transactional log. The database answer (separate the log from the data) may not transfer to a system whose log and data are the same markdown file. If C2A2 solves this, that is plausibly an original contribution.
