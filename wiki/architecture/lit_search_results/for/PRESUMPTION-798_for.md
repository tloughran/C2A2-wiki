  Original statement: [inferred] That a run which produces no output has produced no evidence. Nine of today's twenty-five runs reached no deliverable, and in every downstream artefact they are simply absent — not failed, not pending, absent. Nothing in the fleet holds a manifest of what was *supposed* to run, so absence has no place to register. The presumption is that the set of things that happened is recoverable from the set of things that wrote something.

  Claim as tested here (polarity note): the presumption is worded as the DEFECTIVE belief, so the proposition searched FOR is the CORRECTIVE CONVERSE, in three parts: (i) a run that produces no output HAS produced evidence, and the set of runs that executed is NOT recoverable from the set of runs that wrote something; (ii) recovering it requires an A-PRIORI ROSTER OF EXPECTED RUNS — a manifest — against which absence registers as a POSITIVE state rather than as nothing, and this roster is a named, standard artefact in several mature practices; (iii) absent that roster, every downstream count, rate and trend is computed over a SELF-SELECTED RESPONDING POPULATION and is a biased estimator whenever the silence mechanism is non-random. "SUPPORTED" below means 14b's worry is well grounded, and is equivalently evidence AGAINST the presumption as worded.

  Strength of support: Strong (for the corrective proposition), with the qualification that the strength is unevenly distributed across the three parts — see Caveats (b).

  Summary: The corrective proposition is well supported and each of its three parts has a distinct literature. Part (i) — absence is evidence and is not recoverable from the written record — is the omission/crash distinction, which is fifty years old, is already in this register under PREMISE-141, and rests on the impossibility result that absence carries no information except relative to a declared expectation. Part (ii) — the fix is a manifest — is where the search found the most useful material, because two mature practices independently converged on the same object: heartbeat monitoring services are architecturally incapable of operating without a per-job registration that constitutes the roster, and batch-processing completeness controls have used manifests and control totals for the same purpose for decades, with the explicitly stated aim of detecting missing items rather than validating present ones. The S3 Batch Operations shape is the one worth naming: a manifest declares the intended population and the completion report is keyed to that manifest, so a member that produced nothing appears as a member that produced nothing. Part (iii) — the estimation consequence — is the item's Critical-risk clause and it is correct as stated: aggregates computed over a set that selected itself by responding are biased estimators under non-random missingness, and the direction of the bias here is predictable rather than unknown, because silence correlates with error, overrun and difficulty, i.e. with exactly the conditions the metrics purport to detect. The clinical test-follow-up literature supplies the closest measured analogue and it is not reassuring: in the best-studied real system with this exact structure, the majority of results were never reviewed and the failure persisted for years because nothing held the expectation set. The item's own phrasing — "absence has no place to register" — is, in the terms of every source located, the correct diagnosis rather than a metaphor.

PREMISE-141 was validated on 2026-08-05 from an observation of four silent runs and already holds the three-state model, the omission/crash distinction, the deadline-alarm remedy, and the correlated-termination arithmetic. If a disposition mints a new premise restating any of these, it is doing the thing 15c's own 2026-08-14 run notes identify as "the failure mode this register is accumulating." The defensible increments are narrow and are named in the register check: the MANIFEST AS AN ENUMERABLE ARTEFACT (a denominator, not a set of independent detectors) and the ESTIMATION CONSEQUENCE (self-selected respondent set, not self-certification). Everything else is a non-application finding about PREMISE-141, and the more useful routing may be a REVISE against 141's non-enforcement rather than a new premise.
    (b) THE THREE PARTS ARE NOT EQUALLY EVIDENCED, and part (iii) is the weakest despite being the highest-risk. Parts (i) and (ii) rest on established taxonomy and on practices whose existence is directly demonstrable. Part (iii) rests on a transfer: the missing-data literature was built for survey and clinical-trial data with sampled units and a defined target population, and I located NO study measuring bias in system-generated operational metrics arising from silent job failure. The argument that C2A2's corpus is MNAR rather than MCAR is an INFERENCE FROM THE PLAUSIBLE MECHANISM (silence correlates with difficulty), not a measured finding, and it should be carried as such. It is also directly testable in-house and cheaply — see the recommendation.
    (c) THE MANIFEST HAS A COST AND A FAILURE MODE THAT THE SOURCES UNDERSTATE, AND PREMISE-053 PREDICTS IT. A manifest is another artefact that can go stale: a roster that no longer matches the actual scheduled set will report confidently on a fiction, and a run absent from the manifest is invisible to reconciliation by construction. Vendor documentation does not discuss this because the vendor's manifest is maintained by the user. The mitigation is that the manifest must be DERIVED from the scheduler's own configuration rather than hand-maintained beside it — but nothing located this run addresses the derivation problem, and this is a real gap.
    (d) PUBLICATION AND VENDOR BIAS, DECLARED. Sources 1 and 3 are documentation written by parties selling the practice. They are cited for the EXISTENCE AND SHAPE of the practice, which is what the item asks about, and not as evidence that it works. I found no controlled comparison of manifest-based reconciliation against exception-only reporting, and I should not imply one exists.
    (e) PER PREMISE-777, "nine of twenty-five" is an unmarked self-report by the run that counted it, and — as PRESUMPTION-801 in this same batch observes — the counting predicate for "reached no deliverable" is not stated anywhere. The argument here does not depend on the number. One run that executed and left no trace is enough to establish that the written record is not a faithful sample of the executed record; the ratio matters only for estimating the size of the bias, which is exactly what cannot currently be done.
    (f) THE ITEM'S STRONGEST INTERNAL EVIDENCE CUTS BOTH WAYS. 14b notes that one reviewer's contract says "Keep your run quiet unless something needs Tom's attention" and that the run was dead. That is a genuine self-exemplifying case. But it also shows that exception-only reporting was a DELIBERATE DESIGN CHOICE made for a real reason (noise suppression), not an oversight — and the literature located here (Healthchecks' MAILTO critique, PREMISE-138 clause 3 on saturated channels) agrees that the reason is legitimate. The corrective is therefore NOT "make every run report"; it is to separate the LIVENESS channel, which must be affirmative and machine-read, from the ATTENTION channel, which should stay quiet. Any disposition that reads this item as licence to make runs noisier is misreading it.

  Recommendation: SUPPORTED (Strong) for the corrective proposition; equivalently NO-SUPPORT-FOUND for the presumption as worded. The disposition should be narrow, because PREMISE-141 already holds most of it. Two things are worth carrying. First, the MANIFEST: a roster of expected runs, derived from the scheduler configuration rather than maintained beside it, against which each day's observed set is reconciled — so that a run which produced nothing appears in the record AS a run which produced nothing. This is the denominator PREMISE-141's deadline-alarm remedy silently assumes and which no premise requires to exist. Second, the ESTIMATION CONSEQUENCE, which is testable in-house at low cost and should be tested rather than asserted: for the runs already known to have been silent, classify each by whether the silence looks error-correlated or benign, and check whether the silent population differs from the speaking population on any dimension a downstream metric uses. If it does not, the corpus is approximately MCAR and the existing metrics survive with a widened interval. If it does, every rate in `metrics/` is a rate over the easy cases and must be relabelled per PREMISE-140. Caveat (b) should carry forward explicitly: the MNAR claim is currently an inference from a plausible mechanism, not a measurement, and the whole Critical-risk grading rests on it.
