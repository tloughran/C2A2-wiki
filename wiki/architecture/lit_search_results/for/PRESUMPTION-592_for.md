  Sources:
    1. Lamport, L. (1977). "Proving the Correctness of Multiprocess Programs." IEEE Transactions on Software Engineering SE-3(2):125-143; with Alpern, B. & Schneider, F.B. (1985). "Defining Liveness." Information Processing Letters 21(4):181-185. — The decisive theoretical support. The safety/liveness partition establishes that a liveness property ("this run terminates") is not refutable or confirmable by any finite prefix of an execution: for any finite observation, the property may still be satisfied by some extension. An artifact-freshness check is by construction a finite observation of a prefix. It therefore cannot, in principle, certify termination — it can only certify that some output was written. This is the strongest possible form of 14b's claim: the watchdog is not merely lacking a symbol for "still running", it is using an evidence class incapable of distinguishing the two cases.
    2. Fischer, M.J., Lynch, N.A. & Paterson, M.S. (1985). "Impossibility of Distributed Consensus with One Faulty Process." Journal of the ACM 32(2):374-382. — The canonical impossibility result, and its underlying lemma is exactly 14b's point in the distributed setting: in an asynchronous system, a process that is merely slow is indistinguishable from a process that has crashed, on the basis of observed messages alone. The watchdog observes artifacts, not the task; slow-and-still-writing versus done-and-quiescent is the same indistinguishability. Support for the structural claim, not merely the local one.
    3. Chandra, T.D. & Toueg, S. (1996). "Unreliable Failure Detectors for Reliable Distributed Systems." Journal of the ACM 43(2):225-267. — The constructive counterpart, and the strongest support for 14b's implicit remedy. Chandra & Toueg formalise failure detectors by completeness and accuracy properties and show that useful ones are necessarily unreliable but must *declare* their unreliability class. A monitor that emits PASS/FAIL/CANNOT-CHECK without a state for "no terminal signal observed" has an unstated accuracy property; the literature's standard is that the accuracy property be stated so downstream consumers can reason about it. This licenses 14b's specific complaint about the missing symbol.
    4. Isermann, R. (2006). *Fault-Diagnosis Systems: An Introduction from Fault Detection to Fault Diagnosis*. Springer. (Frozen/stuck-at sensor fault class.) — Direct support for the analogy 14b draws to PREMISE-110. The stuck-at-nominal fault is defined by a sensor whose output remains within its valid range while ceasing to track the process; range and plausibility checks pass by construction, so the fault is invisible to exactly the class of check most commonly deployed. A file that exists and is recent is the same signal: in-range, and silent about the process it is supposed to track.
    5. Sculley, D. et al. (2015). "Hidden Technical Debt in Machine Learning Systems." NIPS 28:2503-2511. — Supplies the engineering-practice support and the countermeasure: undeclared and unstable data dependencies degrade systems without raising failures, and the recommended fix is explicit dependency declaration so that absence is an event rather than a silence. Transposed: the run's terminal state should be a declared, asserted output of the run, not inferred from its side-effects.
    6. Cron/batch-monitoring practice literature (heartbeat monitoring; batch-processing monitoring guides, 2026). — Applied corroboration that the industry standard is precisely what the C2A2 watchdog lacks: the completion ping is placed at the *end* of the script so that it fires only on success, jobs are tracked across queue/execution/completion rather than by output inspection, and the explicit guidance is that "a job starting does not mean it succeeded." Heartbeat-with-terminal-state and sentinel-on-exit are the named patterns. Practitioner-grade, not peer-reviewed, but convergent and directly on the mechanism.
    7. Data-observability freshness literature (Datadog data-observability monitor documentation; freshness-SLA practice, 2025-2026). — Support in the adjacent direction: freshness monitors are documented as detectors of *staleness*, i.e. they answer "has this been updated recently", and the vendor and practitioner material is explicit that a freshness check is not a correctness or completeness check. The proxy is well characterised in the literature by what it does *not* certify.

  Strength of support: Strong

  Summary: Strongly supported, and EXTERNALLY ANCHORED (named external referents: Lamport 1977 in IEEE TSE; Alpern & Schneider 1985 in IPL; Fischer, Lynch & Paterson 1985 in JACM; Chandra & Toueg 1996 in JACM; Isermann 2006, Springer; Sculley et al. 2015 in NIPS 28). The literature converges from three independent directions on 14b's claim, and the theoretical result is unusually clean: termination is a liveness property, liveness properties are not decidable from a finite observation, and artifact inspection is a finite observation. The watchdog's PASS is therefore not a weak certificate of completion but a category error — it certifies a safety-class fact (an output exists, recently) and reports it as a liveness-class fact (the run finished). Chandra & Toueg add the constructive half: unreliable detectors are acceptable and unavoidable, but their accuracy class must be declared; the missing "still running" symbol is a failure to declare, not merely a gap in coverage. Isermann's stuck-at fault class supplies the exact analogy 14b drew to PREMISE-110 and confirms it transfers: a signal that stays in-range while ceasing to track is invisible to in-range checks. The applied literature names the remedy at low cost — a terminal-state assertion emitted by the run itself, per Sculley et al.'s declared-dependency principle.

  Caveats: (a) This search supports the *impossibility in principle*; it says nothing about the false-green RATE, which is 14b's stated settling quantity. A proxy can be logically incapable of certifying completion and still be right 99.9% of the time in a fleet whose tasks reliably finish before the check. The observed instance is n=1. Nothing here licenses a claim about magnitude, and PREMISE-124's discipline applies: the rate is currently unmeasured, and this file must not be read as evidence that it is high. (b) Domain transfer: FLP and Chandra & Toueg concern asynchronous message-passing systems with a formal failure model; the C2A2 scheduler is a local task runner where the terminal state is in fact observable by cheaper means (exit status), so the impossibility results transfer as a conceptual argument about the chosen evidence class rather than as a theorem about the system. Where the terminal state IS available and simply not consulted, the situation is better than the theory implies, not worse. (c) Source 6 and source 7 are practitioner and vendor material, cited for the mechanism and the named patterns rather than for measured rates; they carry a commercial incentive toward describing existing monitoring as inadequate. They are convergent with the peer-reviewed sources but should not be weighted as independent empirical evidence. (d) Search scope: four targeted searches across concurrency theory, distributed systems, fault diagnosis and monitoring practice. One literature reached for and not exhausted: measured false-positive/false-negative rates for health checks and readiness probes in production orchestration systems, which is the only material that would speak to the rate rather than the possibility. Moderate search scope; a rate-bearing source would be the useful addition.
