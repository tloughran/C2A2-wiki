      producer-side count (PREMISE-168) and will read as compliance while the execution rate stays at
      the measured zero.
    - **The empirical stratum has no owner and nothing in this item creates one.** The 15d flag's words
      are "the cost of the unassigned measurement role." PREMISE-026 holds at High confidence that
      remediation of a long-unowned queue "requires owner assignment, not item-by-item action." A
      format rule is item-by-item action.
    - **If the item is adopted and the rate does not move, the estate will have burned its best natural
      experiment.** Once every test is written into a FAIL row there is no prose arm left, and the
      differential — which no external study supplies — becomes unmeasurable in-house.
    - **Density, not volume, is the live hazard.** Ancker's measured effect is a 30% drop in acceptance
      per additional reminder per encounter. Converting prose notes into machine-readable rows *adds
      rows*. A remedy that increases the count of structured items competing for one runner's attention
      is, on the best-measured mechanism in this literature, directionally harmful.

  Mitigations available:
    - **Run the differential before the schema change, not after.** The estate holds both arms right now
      and will not for long. Classify every named in-house test of the last N days as (i) prose beneath
      a headline or (ii) inside a machine-readable failing row, and cross-classify each by **whether a
      scheduled agent's own procedure required it to read that artefact** and by **whether the test's
      topic was that agent's subject**. Report with denominators per PREMISE-168. If placement separates
      the outcomes *after* addressing and topic are held fixed, the item is validated and deserves its
      remedy. If it does not, PREMISE-164 already had the answer and the remedy should be an addressing
      rule.
    - **Prefer the addressing remedy, which is equally cheap and is register-held.** PREMISE-164's own
      in-house test shape applies verbatim: for each declined test, does the task file of the next
      scheduled run of the relevant agent **name** the artefact the test was written to as a required
      read? Where the answer is no, the fix is a task-file edit — the same order of cost as a schema
      change, against a mechanism the register has already validated.
    - **Assign the empirical stratum a runner.** This is the estate's own recommendation, 16 runs old and
      unactioned, and it is the only intervention that addresses a service rate of zero. PREMISE-119 is
      explicit that where service is zero "no reduction in arrivals bounds the queue" and steady-state
      relations do not hold at all.
    - **Keep what the counter-example actually demonstrated: attach the remedy, not the location.** The
      transferable property of ASSUMPTION-1384 is that the FAIL **carried a runnable one-liner**. Google's

      be *runnable as written* is a stronger and better-evidenced rule than requiring where it sits.
    - **Do not file a format rule as discharging PRESUMPTION-974.** 974's Critical question is whether a

  STEELMAN:
    Item: PRESUMPTION-983
    Strongest counterargument: The AGAINST case above proves that placement is *not sufficient*, and then
      quietly treats that as proof it is *not operative* — which is a different and much stronger claim
      that none of the evidence establishes. Every external source here measures a system where the

      staring at a dashboard. C2A2's readers are **scheduled agents that do not skim, do not tire, and
      do not develop desensitization** — the three mechanisms carrying sources 3, 4 and 6 are precisely

      `max(timestamp) from events` in a structured field can execute it without a judgement call, whereas
      the same instruction embedded in a paragraph requires the agent to first decide that a test is
      being named, then extract it, then decide it is in scope — three inference steps, each a place to
      stop. That is a real mechanism, it is specific to agent readers, and no source in this file tests
