  Strength of challenge: Moderate

  Summary: The technical finding — that a head-anchored regex reads every trailing enumerated id as absent — is corroborated rather than contradicted by the regex literature, and no source disputes that deleting on a false absence is unrecoverable. The challenges are three. First, the item's protective inference ("the agents caught it") is fragile: the automation-bias literature says operator detection of automated error is unreliable and does not improve with training, so this catch is not evidence of a working control. Second, the implied remedy of reversible-by-default deletion carries documented costs — misleading referential semantics, unbounded retention, and a false sense of closure when a "deleted" record's links stay live — so reversibility is a trade, not a strict improvement. Third, Knight & Leveson's result on correlated faults means two co-designed instruments failing the same way is weak evidence about the size of the affected class; it is equally consistent with the bug being pervasive.

  Specific risks: If C2A2 responds by adding a soft-delete tier and treating the danger as handled, it acquires a retention surface that grows without bound and a query layer that silently returns tombstoned rows to readers who did not filter — a correctness failure at read time rather than at delete time. If it responds by fixing two regexes and stopping, the head-id bug plausibly remains in every other instrument built on the same citation-shape assumption, unmeasured. If it responds by requiring agent sign-off before destructive passes, the automation-bias evidence predicts that sign-off degrades to a rubber stamp as the pass becomes routine, which is worse than no gate because it manufactures an audit trail of approvals. Over-correcting the other way — blocking all irreversible operations — leaves the memory store to accumulate residue indefinitely, which is the failure the retirement pass exists to prevent.

  Mitigations available: Test the instrument against a labelled corpus rather than repairing it by inspection — measure false-absence rate directly and set a numeric precision floor before any destructive pass is permitted. Separate detection from action: let the regex propose, and require an independent, differently-implemented confirmation (not a second regex derived from the same assumption) before deletion. Stage deletion as export-then-remove with a dated, off-path archive rather than an in-table soft-delete flag, avoiding the referential-integrity anti-pattern while preserving recovery. Cap the blast radius per pass (N entries) so a systematic false absence cannot delete the corpus in one run. Periodically inject known-present trailing ids as canaries and alert if the instrument reports them absent.

  STEELMAN:
    Item: ASSUMPTION-1129
    Strongest counterargument: The item reads its own near-miss as a success of oversight, but Parasuraman & Manzey's finding is that oversight of automation fails in exactly this configuration and that expertise and training do not fix it — so what happened today was luck, and the item draws the wrong lesson if it concludes that agent review is a control. Meanwhile the natural remedy, making deletion reversible, is a documented anti-pattern: soft-deleted records mislead the data model, grow unbounded, and give a false sense of closure while live references persist, so "reversible by default" converts a loud, detectable failure into a quiet, chronic one. And Knight & Leveson's correlated-fault result means the fact that *two* instruments shared the head-id bug is not comforting evidence of a bounded problem — co-designed artefacts fail together, so the true extent is unknown and fixing the two observed cases may leave the class untouched. The item's severity rating is right; its implied response is under-specified and its confidence in human-in-the-loop catching is unsupported.
    What would need to be true for C2A2 to be safe: (a) the false-absence rate of every instrument that can authorise deletion is measured against ground truth, not argued from code reading; (b) destructive authority is gated on a measured precision floor rather than on an agent's review; (c) recovery is real — an archive that has been restored from at least once in a drill, not a flag column that has never been exercised; (d) blast radius per pass is bounded so a systematic error cannot be catastrophic; (e) the two found instruments are treated as a sample from a correlated population, and the rest of the population is enumerated and tested.
    How to test: Build a labelled fixture of memory entries with known citation shapes, including enumerated citations with 2–6 trailing ids. Run every deletion-authorising instrument against it and report per-instrument false-absence rate. Then run a shadow retirement pass in dry-run mode over the live corpus and diff its proposed deletions against a differently-implemented reference extractor; any entry proposed for deletion that the reference finds present is a counted false positive. Separately, run a restore drill: pick ten already-retired entries and attempt recovery under the current mechanism, timing and recording success — this is the only way to know whether "reversible" is true.
