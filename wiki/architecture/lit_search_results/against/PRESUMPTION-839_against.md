  Sources:
    1. Ecological fallacy [established-work; Robinson's 1950 result is the canonical source, cited here without page reference]. Restated in located material as "the mistaken assumption that relations evident at an aggregate level also obtain at the individual level" — and the inference runs equally badly in the other direction, which is the direction PRESUMPTION-839 takes. Challenge: inferring a fleet-level rate from a within-lineage count is a cross-level inference with no warrant. The two levels can disagree in magnitude, and under the paradox conditions they can disagree in sign.
    2. Simpson's paradox [established-work]. Characterised in located material as a trend that appears in several groups of observational data and disappears or reverses when the groups are combined, arising when a confounding variable strongly influences the relationship. The operational signature is stated plainly in one located source: "A global KPI can be red (bad), but all your regional managers report green (good) — this is the classic signature of the paradox." Challenge: this is the item's finding restated as a textbook case. Six correct per-lineage counters and no actionable fleet signal is exactly the configuration the paradox describes, and it means the six counters cannot be repaired by being made more accurate; they are the wrong stratification.

  Strength of challenge: Strong

  Summary: The presumption is a named statistical error with a named operational consequence. Inferring a fleet-level property from a within-lineage count is cross-level inference of the kind the ecological fallacy prohibits, and under Simpson's-paradox conditions the two levels can disagree not only in magnitude but in sign — the located restatement of the operational signature ("global KPI red, every regional manager green") is the item's own observation in another vocabulary. The distributed-systems literature supplies the same result as a failure mode: gray failure is formalised as differential observability, a divergence between what the system is doing and what the detector sees, and it is described as the mechanism behind most cloud incidents. The sharpest evidence is from multi-agent security, where per-agent detection thresholds are shown to be systematically evadable by distributing events beneath them so that every per-agent counter reads normal while the fleet-level pattern is unmistakable under centralised correlation; the aggregation boundary is itself the exploitable object. The item's own data — six counters, all correct, none actionable — is precisely the state these literatures predict. Importantly, the challenge is not that the six counters are inaccurate. They are stipulated correct. The challenge is that correctness at the stratum level carries no information about the fleet without a denominator, and that no increase in per-lineage precision will produce one.

  Specific risks:
    - Correlated failure invisible by construction: a condition affecting the whole fleet at low per-lineage intensity is undetectable in every per-lineage counter simultaneously. The failure mode with the highest blast radius is the one this monitoring design is blindest to.
    - Threshold gaming without an adversary: any process that spreads work across lineages will naturally suppress per-lineage counts. Load balancing itself defeats the detector.
    - False reassurance from concordance: six counters agreeing that nothing is wrong looks like corroboration and is instead six views of the same blind spot. This compounds directly with ASSUMPTION-1150 — apparent agreement among non-independent observers is not evidence.
    - No base rate, so no threshold is calibratable: without a fleet denominator there is no way to know whether "three consecutive failures" is normal or extreme, so every threshold in the system is arbitrary.
    - Sign reversal, not just attenuation: under Simpson's-paradox conditions the fleet trend can run opposite to every stratum trend, so acting on per-lineage counters can be worse than not acting.
    - Root-cause attribution to the lineage: with only per-lineage evidence, a fleet-wide cause gets attributed to whichever lineage happened to cross a threshold first, misdirecting remediation.

  Mitigations available:
    - Construct the fleet denominator. Every run emits a record to one fleet-level store with a run identifier, lineage identifier, condition flag and timestamp; the streak becomes a query over that store rather than a state carried inside a lineage. This is the whole of the fix and it is not architecturally hard.
    - Correlate across actors with preserved causality, per the multi-agent tracing literature: the object of interest is the condition, not the actor, and it should be counted per-condition.
    - Report rates with denominators, never raw streaks. "Three consecutive" is uninterpretable; "3 of 4 in lineage L, 11 of 96 fleet-wide" is actionable.
    - Detect at the aggregate boundary explicitly: add a fleet-level threshold in addition to per-lineage thresholds, since the security literature shows that per-actor thresholds alone are structurally evadable.
    - Treat concordance among per-lineage counters as a signal of shared blindness rather than corroboration until independence is demonstrated.

  STEELMAN:
    Item: PRESUMPTION-839
    Strongest counterargument: The presumption commits a named fallacy and produces a named failure. A count taken inside one lineage is a count about that lineage; treating it as the fleet's is cross-level inference, and under Simpson's-paradox conditions the fleet trend can not merely differ from the stratum trends but run opposite to all of them — the operational signature is a global metric in the red while every local report is green, which is the item's own observation rendered in the standard vocabulary. The distributed-systems field calls the resulting blind spot gray failure and formalises it as differential observability, describing it as the mechanism behind most cloud incidents. And the multi-agent security literature closes the argument by showing that per-actor thresholds are not merely incomplete but structurally evadable: distribute events evenly beneath the per-agent threshold and every counter reads normal while the fleet-level pattern is plain under centralised correlation. Note what this means for C2A2 specifically. The condition this monitoring design is *least* able to see is the fleet-wide correlated one — the highest-blast-radius failure available — and six correct counters agreeing that nothing is wrong will read as corroboration when it is six instances of the same blind spot.
    What would need to be true for C2A2 to be safe: (a) Failures would have to be genuinely independent across lineages, so that a lineage is a valid random sample of the fleet — which is exactly the assumption a shared harness, shared model and shared prompt scaffolding violate; (b) the per-lineage threshold would have to be low enough that a fleet-wide condition still trips at least one lineage, which requires knowing the fleet base rate, which is the thing that does not exist; (c) no process would distribute work across lineages in a way that suppresses per-lineage counts, which load balancing does by design; (d) concordance among counters would have to be treated as shared-blindness evidence rather than as corroboration.
    How to test: Build the denominator and then check whether the presumption ever held. Emit one fleet-level record per run — run ID, lineage, condition flag, timestamp — for thirty days. Then, retrospectively, compare each lineage's streak against the fleet rate over the same window and compute how often a lineage streak would have led to the correct fleet-level conclusion. That number is a direct measurement of the presumption's accuracy and it requires no change to any existing counter. Additionally, run the adversarial check from the security literature without an adversary: simulate a fleet-wide condition at an intensity just below every per-lineage threshold and verify that the current monitoring reports nothing. If it does, the blind spot is confirmed and its size is quantified.
