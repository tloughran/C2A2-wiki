    1. Okhotin, I. I. & Dorodnykh, N. O., 2025. "Table Header Recognition Based on Large Language Models." VLDB 2025 Workshop: Tabular Data Analysis (TaDA). [VERIFIED — full text fetched from vldb.org/2025/Workshops/VLDB-Workshops-2025/TaDA/TaDA25_14.pdf] — Eight LLMs, 237 tables, six prompt strategies. Even the largest model (405B) tops out at F1 ≈ 80–85% on header identification; recall collapses when headers are not in the first row; models show "false positive header identification" — a systematic tendency to classify any text-bearing cell as a header in dense tables — and "header omission in complex tables." The paper's diagnosis is directly on point: LLMs "were trained using basic tables with a header in the first row; therefore, they tend to use this pattern." The header/data boundary is not decided by the cell's content; it is decided by layout conventions the model has absorbed, which is precisely the failure mode the 1251 ruling is trying to legislate away.
    2. Koci, E., Thiele, M., Romero, O., Lehner, W., 2019. "DECO: A Dataset of Annotated Spreadsheets for Layout and Table Recognition." (ICDAR 2019). [VERIFIED as existing via Semantic Scholar listing and secondary citations; full text not fetched] — 854 Enron spreadsheets annotated at cell level into seven roles: Data, Header, Derived, GroupHeader, Title, Note, Other, by three annotators. The very existence of a seven-way role scheme (not the two-way apparatus/structure split of 1251) is the challenge: real spreadsheets contain cells that are simultaneously label-like and content-like (GroupHeader, Title, Note), and "Header" is explicitly permitted to "span multiple rows and be hierarchical." A binary rule with an escape clause ("unless authored") has no slot for these.
    3. Koci, E., Thiele, M., Romero, O., Lehner, W., 2018. "Cell Classification for Layout Recognition in Spreadsheets." (Springer, IC3K/KDIR revised selected papers, LNCS ch. 978-3-319-99701-8_4). [VERIFIED as existing via Springer listing; full text not fetched] — The Dresden group's ML cell-classification line exists because rule-based header detection ("the accuracy of basic header extraction approaches is not acceptable because spreadsheets allow users to design table layouts flexibly" — paraphrase from the search abstract of Zhang et al., Microsoft Research, "Semantic Table Structure Identification in Spreadsheets") does not generalise. Rules that key on cell length or position — exactly the pre-pass length rule 1251 replaces — are the documented losers.
    4. Zhang, Y. et al. (Microsoft Research), 2020. "Semantic Table Structure Identification in Spreadsheets." [NOT verified beyond search-result abstract; author list beyond first author not confirmed] — Notes that prior work "can identify headers but cannot distinguish different header types," i.e. the header-vs-data question is downstream of a harder question about header *kinds*, which 1251 collapses into one clause.

  Strength of challenge: Moderate

  Summary: The table-understanding literature does not contradict the intuition that labels are usually apparatus; it contradicts the claim that the exception ("unless the table is itself an authored structure") is a decidable class that a reader — human or LLM — can apply reliably. Empirically, header/data discrimination is a learned, layout-driven, error-prone task (F1 ≈ 0.8 ceiling for the best LLMs on clean scientific tables; much worse off the first row), and annotated corpora needed seven cell roles, not two, to describe what they found. The 1251 rule was induced from a single error (eight ladder letters) and is stated as a dichotomy with a judgement-call escape hatch; nothing in the literature suggests "authored structure" has an operational test, and the LLM header-recognition results predict that a worker applying it will default to the first-row/short-text prior the rule was meant to override. Note the rule also inverts the usual direction of error: the literature's dominant failure is *over*-labelling text cells as headers (false positives); 1251 was written to fix an *under*-labelling case, and adds no guard against the more common direction.

  Specific risks: (a) The rule is not decidable without the very judgement it was meant to replace, so it will be applied inconsistently across workers/batches (compounds PRESUMPTION-906 calibration risk). (b) Because it was generalised from one instance (rows 247–250 / 292+), there is no evidence about its behaviour on the other label-bearing rows in 2,402 cells; the DECO role inventory (Title, Note, GroupHeader) names cell kinds the rule does not address. (c) An LLM worker told "labels are structure when authored" may over-apply it and promote ordinary column headings to nodes — the false-positive direction Okhotin & Dorodnykh document as the dominant LLM error.

  Mitigations available: Replace the binary with an explicit cell-role field (Header / GroupHeader / Title / Note / Data, per DECO) so that "authored structure" becomes a row-level annotation rather than an inferred class; enumerate the authored tables by row range in the spec rather than asking workers to detect them; spot-check all cells ≤ 2 chars against the new rule and against the old rule to measure the actual delta.

  Recommendation: PARTIALLY-CHALLENGED

STEELMAN:
  Item: ASSUMPTION-1251
  Strongest counterargument: The rule looks like a principle but is a patch: it was induced from one error and its operative clause ("unless the table is itself an authored structure") is exactly the judgement that the field's best models cannot make reliably. Header/data discrimination is empirically a layout-prior problem, not a content problem — LLMs default to "first row / short text = header" and otherwise over-label text cells as headers. The 1251 escape clause therefore either (i) gets applied by the same prior it is meant to override, in which case it changes nothing, or (ii) gets applied liberally, in which case it manufactures nodes out of column headings. Either way the outline's cell counts inherit an undocumented, non-reproducible decision.
  What would need to be true for C2A2 to be safe: "Authored structure" must be enumerable in advance (a finite, spec-listed set of row ranges), not inferred per cell; the rule must be applied by a single pass with the list in hand; and the count of cells whose classification changed under the rule must be small and inspected.
  How to test: Take every cell ≤ 2 characters (the original trigger population) plus every cell in a row that has a label-like left neighbour; have two independent workers apply the 1251 rule blind; measure agreement. If κ is below ~0.7, the class is not decidable as written. Cheap: the population is likely < 100 cells.
