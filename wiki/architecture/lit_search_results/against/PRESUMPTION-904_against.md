  Strength of challenge: Moderate-to-Strong

  Summary: Three independent literatures converge on the same objection. Content-analysis methodology (Krippendorff) treats the unit of analysis as a decision requiring its own reliability check and warns against letting the medium's physical units stand in for thematic units. Multi-label text classification exists as a field because single-label assignment to multi-topic units discards information by construction. Retrieval chunking work finds that storage-defined fixed units mix topics and that topic-aligned units perform better. Against this, the C2A2 spec assigns exactly one node per cell with no split or merge operation and no unitizing reliability estimate; the `run_id` facet acknowledges meaning spanning cells but only in the merge direction, and only as a rendering hint, not as a classification unit. No located source studies spreadsheet cells as annotation units specifically, so the challenge is by transfer; but the transfer is short — a cell in a personal notes spreadsheet is a "physical unit" in Krippendorff's exact sense.

  Specific risks: (a) Long multi-topic cells are filed under one node and invisible to the others; per-node cell counts in the ToC are biased toward whichever topic the worker read as dominant, with no record that a second topic existed. (b) Short cells that are fragments of a single thought across a run are each classified independently, inflating counts and creating spurious node boundaries mid-thought. (c) Because there is no unitizing reliability figure, the coding reliability figures (PRESUMPTION-906 confidence) are, in Krippendorff's framework, uninterpretable — they measure agreement on units that were never validated. (d) The 70 `low` cells are the only current signal; multi-topic cells classified confidently under one node will not appear there.

  Mitigations available: Add an optional `secondary_node` field (cheap, spec-level, keeps one-line-per-cell); sample the longest ~5% of cells by character count and hand-check for multi-topic content (direct empirical test 14b already proposed); allow `run_id` to be a classification unit as well as a rendering unit, so a run can carry one node instead of each cell carrying its own; report a unitizing agreement figure on a 50-cell sample before trusting coding agreement figures.

STEELMAN:
  Item: PRESUMPTION-904
  Strongest counterargument: The pipeline classified 2,402 units it never chose. Content-analysis methodology has held for decades that the medium's physical units (here: cells) are not thematic units, that the choice of unit is a reliability question in its own right, and that coding agreement measured on unvalidated units is not interpretable. The multi-label classification literature adds that "exactly one label" is a lossy constraint whenever units are multi-topic, and the chunking literature adds that fixed, author-incidental units are exactly the ones that mix topics. Every per-node count in the ToC is therefore a count of cells-that-were-read-as-mostly-X, not of X-content, and the error is invisible because the spec has no place to record it.
  What would need to be true for C2A2 to be safe: Tom's cells would have to be, in practice, single-topic — i.e. the author's habit of one-thought-per-cell would have to be strong enough that the physical and thematic units coincide. This is plausible for short cells and doubtful for long ones; it is an empirical property of this corpus, not a general truth.
  How to test: Rank cells by length; take the top 100; have a worker (or Tom) mark how many distinct outline nodes each cell touches. If > ~10% touch two or more, the presumption fails for the population that carries most of the corpus's text. Cost: one worker pass over 100 cells.
