# Community Explorer (Graph + Cards)

**family** graph + table · **tier** T1 · **manifest entry** yes, `community_explorer` — the most complete in v1

## identity
`wiki/community_explorer.html`, 363,456 B, 786 lines (324 KB of it is one inlined
`GRAPH` line, `:175`). Reached as the chapter button `chap-community`
(`explorer.html:425`) and standalone. **Generated** by
`scripts/generate_community_explorer.py` (`main()` `:662-673`; docstring `:4`:
"Builds wiki/community_explorer.html from wiki/community/community_graph.json").
The generator is dated 2026-06-06 and the HTML 2026-09-18; the generator's help
and Ask-AI code does appear in the HTML, so it was plausibly regenerated by the
same script (inferred).

**The Cards sub-view is a separate application** — `wiki/community/index.html`,
loaded in an iframe with a lazy `data-src` (`:148`, set on first Cards click,
`:769`). It has 1,006 records and its own filters, sort, four sub-views and
exports. Entry: `21_nested_subsurfaces.md`.

## purpose
A two-surface instrument: a force-directed graph of 155 curated communities
linked by problem/resource/solution text similarity, plus a Cards directory of
the full 1,006-record seed set.

## entities and fields
- **Graph node**: `id` (`CC-nnn`), `name`, `type` (8 values), `subtype`, `url`,
  `country`, `description`, `problem`, `resource`, `solution`, `prs_quality`
  (109 at 2, 46 at 3). Derived on the page: `degree`, `neighbors`.
  Type counts: Tradition-Constituted Enquiry 24, Scientific Frontier 22,
  Civic & Political 21, Contemplative & Spiritual 21, Local & Embodied 19,
  Interdisciplinary Synthesis 18, Practice Communities 16,
  Professional Guilds 14.
- **Graph edge**: `{source, target, weight}`, weight = PRS cosine similarity
  (≥0.08).
- **Card record**: `Community_ID, Type, Subtype, Community_Name, Country,
  Country_Source, Verified_Link, Verified_Link_Host, Email_Contact,
  Email_Retrieval_Note, Narrative_Description, Narrative_Word_Count,
  Problem_Statement, Resource_Statement, Solution_Statement, PRS_Triplet_Count,
  Source_Directory, Source_Link, Verification_Method, Narrative_Grounding`.

The graph's 156 curated communities were merged into Cards **under their own
`CC-xxx` ids** (`architecture/explorer_tabs_complementarity.md`), so the graph is
a literal id-subset of the cards. That shared key is the one real cross-surface
join in the project, and it is the reason this pair is the best candidate for a
manifest that declares relationships between surfaces rather than only within
them.

## cut
Caps are per tab, rosters per sub-view — the pattern `voice_guide_redesign.md`
§X (`:1645`) was written about.

**Tab level**: `view` (value: graph | cards), bound to `#tab-graph` / `#tab-cards`
and their `.active` class (`:762`, `:769`). Declared in the manifest as `views`.

**Graph view**:

| dim | kind | binding |
|---|---|---|
| types | set of 8 | `#typefilters input[data-type]`; truth is the **lexical** `const activeTypes = new Set(...)` (`:369`), not on `window`; bulk `#types-all`, `#types-none`; `rebuild()` (`:423`) removes nodes from the DOM |
| exemplary | value, bool | `#q3only`, lexical `let q3Only` (`:370`), ANDs with `types` |
| selection | read/action | click `#graph circle` → `showNode` (`:513`); panel `#rightpanel.open #rp-content h3`; close `#rp-close` |
| edge_selection | action | click a `line` → `showEdge`; manifest gesture deferred |
| fit | action | `#btn-fit` (`:566`) |
| hold_forces / show_names | value, bool | `#btn-hold` / `#btn-names` with class `.on`; both manifest-deferred |
| search_lens | value, text | `#search-input`, `#btn-search`, `#btn-clear`, plus `search-ai-mode` and `search-external` checkboxes; `applyLens` (`:599`) **dims non-matches to opacity 0.08 and never filters**; `rebuild()` resets it silently; also a `focus: A ~ B` syntax (`:624`) |
| zoom_transform | read | **not drivable** — `zoom` and `svg` are top-level `const`s |

**Cards view** (nested app; the manifest declares one level of it): roster is
`#cc-card-grid > button.cc-card`, rendering only the first 60
(`CARD_LIMIT`, `community-cards.js:31`), with the true total read from
`#cc-card-status`. **Undeclared**: `#search-input`, `#country-select`,
`#subtype-select`, `#source-select`, `#sort-select`, `#manual-only`, `#geo-only`,
`#type-pills button.pill`, `#page-size`, the four `.cc-tab` views
(cards | map | prs | overview), `#cc-prs-search`.

Two things are genuinely not expressible with the current model, and the manifest
says so itself: the d3 zoom transform, and the **search lens** — which needs a
"highlighted but still present" state the cut vocabulary does not have. That is a
third candidate `kind` alongside `value | set | action | read | address`.

## change signal
The useful signal is the curated set changing, at community grain: an add, a
drop, a type change, a `prs_quality` change — i.e. a new node in
`community_graph.json`, or an edge crossing the 0.08 threshold (inferred). For the
1,006-record directory: new or changed `Community_ID`s, and a record's PRS
statements being sharpened or claimed, which is the promotion event the
complementarity doc describes as the membrane between directory and graph.
Nothing exposes a per-record timestamp; only `meta.generated` ("2026-06-06")
exists, at file level.

## export shape
- Graph CSV: `id, name, type, subtype, country, url, prs_quality, degree,
  description, problem, resource, solution`; edges `source, target, weight`.
  JSON: the node plus `neighbors:[{id, w}]`. **None of this exists.**
- **The nested Cards app already exports**: `#download-csv` →
  `c2a2_community_explorer_filtered.csv`, `#download-json` →
  `c2a2_community_explorer_filtered.json`, rows as filtered, plus
  `#copy-share-link` (`community/app.js:1326-1332`; `index.html:235-237`).
  **The tab shell does not surface them, and the manifest excludes them from
  voice.** This is the only working export in the project and it is two frames
  deep.

## what resisted description
- Nothing records when a record changed (undocumented, not amorphous).
- Whether the HTML was regenerated after the generator's June date (inferred yes).
- The Cards app's pagination (`page` / `size` URL params, `app.js:260-261`) was
  only skimmed — note these are URL params, so the Cards cut is *partly*
  linkable, which no other nested surface manages.
- `COMMUNITY_EXPLORER_REBUILD_SPEC.md` (repo root, 2026-05-21) says "build not
  started"; the generated page postdates it, so the spec is stale.
- Genuinely hard rather than undocumented: the zoom state and the search lens as
  cut dimensions. The manifest already says this about itself, which is the
  behaviour this audit wants from all 24 entries.
