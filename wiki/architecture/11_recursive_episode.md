# Pathway 11: Recursive Episode Publishing

## Purpose

Every substantive Q&A, every plot interrogation, every cross-thinker exchange can become a publishable podcast episode at the end of its life: source dialogue → transcript → episode → distribution → vault re-ingestion. This closes the Karpathy loop at the output end. The wiki grows *by virtue of being explored*. Better retrieval base produces better answers; better answers produce better episodes; better episodes thicken the retrieval base.

It also gives the half-million-word podcast pin its natural reentry point: existing podcasts come *in* as source material; future episodes generated by this system go *out* through the same channel. Symmetric pipeline.

## Function set

The recursive publishing flow has five stages:

1. **Episode candidacy.** Not every exchange is publish-worthy. The system flags candidates: dialogue threads of meaningful length (≥ N turns), threads with substantive cross-tradition content, threads the user explicitly bookmarks. Candidates queue for review or auto-publish, depending on policy.

2. **Episode generation.** A NotebookLM-equivalent pipeline produces a two-voice podcast from the dialogue transcript and the supporting vault context. The pipeline can use NotebookLM directly (if API access) or an equivalent OpenAI / ElevenLabs two-voice synthesis with a small script-generation agent in front.

3. **Episode metadata.** Each generated episode carries: the source dialogue thread (timestamps, participants, vault attestations), the vault nodes referenced, the thinkers in scope, and the publication policy (private / private-link / public).

4. **Distribution.** Public episodes publish to the project's podcast feed (Spotify, Apple Podcasts via a feed aggregator like Buzzsprout or Anchor) and to YouTube (audio + waveform video). Private episodes stay on the project page with link-only access.

5. **Vault re-ingestion.** Every published episode becomes a new vault node, tagged with the thinkers and structure groups it touched. The Sociogram shows it as a regular node, retrievable by the voice agent, linked to the original sources it referenced. Future questions can pull from the episode's content as primary material.

## Architecture sketch

```
dialogue thread (Pathway 01)
        ↓
   episode candidacy check
   ├─ thread length
   ├─ substantive content score
   └─ user bookmark
        ↓
   episode generation
   ├─ script agent (broker-side)
   ├─ NotebookLM API or equivalent two-voice synthesis
   └─ produce: audio file + transcript + metadata
        ↓
   distribution
   ├─ podcast feed publish
   ├─ YouTube upload (audio + waveform)
   └─ project page link
        ↓
   vault re-ingestion
   ├─ episode becomes new markdown node
   ├─ tagged with thinkers, structure groups
   ├─ linked to source dialogue and vault attestations
   └─ Sociogram includes it on next regeneration
```

## Decisions taken

- **Symmetric in/out pipeline.** The same architecture that publishes episodes also (eventually) ingests the half-million-word existing podcast corpus. Both directions share the transcript-to-vault-node mechanism.

- **Episodes are first-class vault nodes.** Not external artifacts referenced from the vault, but content within the vault, retrievable by the agent on subsequent questions. This is what closes the recursive loop.

- **Provenance in every episode.** The published audio is preceded by an attribution block ("this episode draws on dialogue from session X with vault nodes A, B, C"). The transcript carries the full provenance footer. Listeners can see what the system was working from.

- **Publication policy gating.** Not everything published. Default: private until explicit promotion. Avoids the surveillance-of-conversation pattern.

## Open questions

- **Episode review queue.** Auto-publish vs. human-in-the-loop. Strawman: human review for the first N episodes (calibration), then auto-publish for content above a confidence threshold. Worth Tom's judgment.

- **Episode generation provider.** NotebookLM has the highest quality two-voice synthesis today but API access is limited. OpenAI two-voice TTS is cheaper and accessible; quality is rising. Strawman: NotebookLM if accessible by ISME, OpenAI fallback otherwise.

- **Distribution platform.** Buzzsprout, Anchor (Spotify for Podcasters), or a self-hosted feed. The trade-off is reach vs. control. Tom can weigh.

- **Half-million-word ingestion priority.** The pinned podcast corpus could become its own pathway when prioritized. Likely worth scheduling after the first ISME-generated episodes have validated the publish-side pipeline.

## Edges

- **broker (00):** episode generation, metadata stamping, and publish gating all route through the broker.
- **voice_dialogue (01):** primary source of episode candidates; published episodes feed back as retrievable content for the agent.
- **space_time_peeling (10):** YouTube live broadcasts and async comments become source material for podcast episodes about the conversation itself.
- **outreach_automation (12):** new episodes can be the content handle for content-grounded DMs and lab invitations.
- **durable_memory (16):** episodes thicken the persistent layer; returning visitors can be pointed at episodes covering their prior threads.
